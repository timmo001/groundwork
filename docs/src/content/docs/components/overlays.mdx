## Popover

Whatever a button asks or offers opens next to that button, not in the middle of the screen, so it stays tied to what was pressed. That covers a confirmation, a rename, a small form and a question that follows the action, such as asking to restart after a save: it opens from the Save button. On phones it's a bottom sheet.

<Demo id="popover">
  <gw-button variant="danger" data-opens="forget-device">Forget device</gw-button>
  <gw-popover id="forget-device" confirm>
    <p>Forget Living room speaker? It has to be paired again before it can connect.</p>
    <gw-button slot="actions" size="small" variant="neutral" appearance="plain" value="cancel">Cancel</gw-button>
    <gw-button slot="actions" size="small" variant="danger" value="forget">Forget</gw-button>
  </gw-popover>
  <gw-button variant="neutral" appearance="filled" data-opens="rename-section">Rename</gw-button>
  <gw-popover id="rename-section" heading="Rename section">
    <gw-input label="Name" value="Living room"></gw-input>
    <gw-button slot="actions" size="small" variant="neutral" appearance="plain" value="cancel">Cancel</gw-button>
    <gw-button slot="actions" size="small" value="save" data-needs-changes>Save</gw-button>
  </gw-popover>
  <gw-button data-opens="restart-after-save">Save settings</gw-button>
  <gw-popover id="restart-after-save" heading="Restart now?">
    <p>The new settings take effect after a restart.</p>
    <gw-button slot="actions" size="small" variant="neutral" appearance="plain" value="later">Later</gw-button>
    <gw-button slot="actions" size="small" value="restart">Restart</gw-button>
  </gw-popover>
</Demo>

Keep a popover to one or two fields. A longer form is a view of its own, not a popover or a dialog stacked on the page.

| Attribute or method | What it does |
| --- | --- |
| `show(anchor)` | Opens under `anchor`, or above it when there's more room there, lined up with the edge on the button's side of the screen. Without one it opens in the middle, which is only for something nothing on screen started |
| `heading` | A heading. A confirmation that's only a question leaves it out, and the question is the message |
| `confirm` | Makes it an `alertdialog`, for a question that needs an answer |
| `close(value)` | Closes it; `returnValue` holds the value when it fires `close` |

It's on the Popover API, in the top layer, so a scrolling parent never clips it. Focus starts on the first action (put Cancel first, so Enter never confirms by accident) and goes back to the button afterward. It follows the button as the page scrolls, and it's a bottom sheet below 600px wide. Esc and a click outside close it the same way a [dialog](#closing) closes.

## Closing

Popovers and dialogs that hold edits close the same way, so a stray key or click never throws work away. Try it with Rename above: Save stays off until the name changes, and once it has, Esc asks first and a click outside does nothing.

| While | Esc or the close button | A click outside or on the backdrop | Save |
| --- | --- | --- | --- |
| Nothing has changed | Closes at once | Closes at once | Disabled |
| Something has changed | Asks "Discard your changes?" first | Does nothing | Enabled |

An `input` or `change` event from the content marks it changed, and `show()` clears that. Set `dirty` to mark it yourself, such as after an edit made through script. Put `data-needs-changes` on the actions that only make sense after a change, such as Save, and they're disabled until then. Cancel and the other actions close it straight away, since pressing them is a choice. Nothing confirms a save with a toast: the popover closing, or the dialog closing, is the confirmation.

| Attribute or property | What it does |
| --- | --- |
| `dirty` | Whether the content changed since it opened. Set by edits, cleared by `show()` |
| `data-needs-changes` | On an action, keeps it disabled until something changes |

## Dialog

  <gw-button variant="neutral" appearance="outlined" data-opens="signed-out" icon="M10,17V14H3V10H10V7L15,12L10,17M10,2H19A2,2 0 0,1 21,4V20A2,2 0 0,1 19,22H10A2,2 0 0,1 8,20V18H10V20H19V4H10V6H8V4A2,2 0 0,1 10,2Z">Expire the sign-in</gw-button>
  <gw-dialog id="signed-out" heading="Signed out">
    <p>Your sign-in expired. Sign in again to keep working; nothing you've done is lost.</p>
    <gw-button slot="actions" variant="neutral" appearance="plain" value="close">Close</gw-button>
    <gw-button slot="actions" value="sign-in">Sign in</gw-button>
  </gw-dialog>
</Demo>

Only for something nothing on screen started that blocks the whole app until it's answered, such as an expired sign-in. App-wide state you can work through, such as a lost connection, a needed restart or a new version, is a slim bar instead, and anything a button starts is a [popover](#popover). The button in the demo stands in for the sign-in expiring.

It's a native `<dialog>` opened as a modal, so focus moves into it and back when it closes, and the page behind can't be reached. It has a close button in its header, and Esc, the close button and the backdrop follow the [closing rules](#closing). Open it with `show()`. A button in the `actions` slot with a `value` closes it with that value, which is in `returnValue` when it fires `close`.
