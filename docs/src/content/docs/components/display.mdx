### Linking from the heading

An `href` link lives in the card's shadow root, so it isn't in the page's HTML and can't take a `target` or `rel`. When it needs to be there, such as a project card opening its repository in a new tab, put an `<a>` in the `heading` slot instead. A click anywhere on the card follows it, except on another control inside, such as a button, and the card shows the link's hover and focus:

## Expansion panel

<Demo id="expansion" layout="stack">
  <gw-expansion heading="Network" description="Wake on LAN, interfaces and ports" open>
    <gw-facts items='[{"label":"Interface","value":"enp5s0"},{"label":"Address","value":"192.168.1.20"}]'></gw-facts>
  </gw-expansion>
  <gw-expansion heading="Advanced" description="Logging and diagnostics">
    <p>Log level, crash reports and the debug endpoint.</p>
  </gw-expansion>
  <gw-expansion heading="Backups" description="Nightly, kept for 30 days">
    <gw-button slot="actions" size="xs" appearance="plain">Back up now</gw-button>
    <p>The last backup finished at 03:12.</p>
  </gw-expansion>
</Demo>

A heading that glides its content open and shut, on a native `<details>`, so find-in-page and the keyboard work as usual. `open` reflects its state, and it fires `toggle`. Slot an icon in `icon`, and buttons in `actions` to keep them in the summary row, where pressing them doesn't open or close it.

Give it a `storage-key` to keep whether it's open in this browser once someone opens or shuts it; until then, `open` sets how it starts. `--gw-expansion-summary-height` sets the summary row's least height (`3rem`) and `--gw-expansion-toggle-size` the chevron's circle (`2rem`).

When the content costs something to build, such as a long list or a diff, set `draw` instead of slotting it. It's called with a container the first time the panel opens, a frame later, so the panel opens at once with skeleton lines and the content follows. A new `draw` draws again while it's open, and waits while it's shut. The container sits in the light DOM, so the page's own styles reach what's drawn.

```ts
expansion.draw = (target) => render(changesTable(changes), target);
```

A bar for a value in a range, with `min` (0) and `max` (100). Past `high` it turns warning and past `critical` danger, unless a `tone` is set. `display` replaces the percentage shown beside the label.

## Table

<Demo id="table" layout="stack">
  <gw-table label="Processes" sort="cpu" descending row-key="pid" contained data-sample="processes"></gw-table>
</Demo>

Rows of data that sort by a header press and search every column, built on TanStack Table. Only the rows on screen are drawn, by TanStack Virtual against the window's scroll, or the table's own frame with `contained`, so thousands of rows stay quick, and rows can be any height.

| Attribute | What it does |
| --- | --- |
| `columns` | The columns: `id`, `header`, and `numeric`, `wide`, `sortable` or `searchable` |
| `rows` | The rows. A column reads the row property its `id` names |
| `sort`, `descending` | The column it sorts by, and whether highest or latest comes first |
| `query`, `search`, `search-from` | The search text, whether there's a search field (`auto`, `always` or `never`), and how many rows `auto` adds one from (`8`) |
| `group` | The column whose values it groups the rows by. Each group gets a heading with its name and a chip counting its rows, which folds it away when pressed. That column doesn't show, since the headings name its values |
| `groups-collapsed` | Starts every group folded away, for long lists. Pressing a group's chip still opens it |
| `toggled-groups` | The groups, by value, pressed from how they start, so a page can keep which are folded |
| `contained` | Scrolls inside its own frame, up to `--gw-table-max-height` (`70vh`), with the header kept in view, rather than with the page. Each group's heading stays pinned under the header while its rows scroll past |
| `more`, `more-rows`, `more-margin` | There are rows still to load after these. `more-rows` skeleton rows (`3`) follow the last, and as they come within `more-margin` pixels (`400`) of view it fires `more` |
| `storage-key` | Keeps the sort, search and folded groups someone set in `localStorage` under this key, so the table comes back as they left it. Only what they changed is kept, so the other attributes still set the rest |
| `row-key` | The row property that identifies each row, so it keeps its place across updates |
| `label`, `search-label`, `empty-label`, `no-match-label` | Its name, and the text it shows, for an app in another language |

Grouped by day, with older pages loading as it scrolls. Each day's heading stays pinned under the header while its runs scroll past, and skeleton rows stand in for the next page until it comes in:

<Demo id="table-grouped" layout="stack">
  <gw-table label="Runs" group="day" row-key="id" search="always" search-label="Search runs" contained data-sample="runs" data-pages="6"></gw-table>
</Demo>

Set `columns` and `rows` as properties in code, and a column can take functions: `value` reads what sorting and search use, `cell` draws the cell as any node, such as a link or a chip, and `groupLabel` names a group from its value. A `toolbar` slot sits beside the search field, for a Filters button that opens a sheet of `gw-filter`s. It fires `change` when the sort, search or folded groups change; read `sort`, `descending`, `query` and `toggledGroups`, such as to keep them in the URL. To keep them in this browser, give it a `storage-key` instead.

The search field is a [`gw-input`](/components/inputs#input), the `search` part, so it looks and behaves as every field does; `--gw-table-search-scale` sizes it (`0.9`), and `--gw-table-search-width` and `--gw-table-search-max-width` set how wide it starts and grows (`14rem` and `24rem`). The group counts are `gw-chip`s, the `group-count` part, sized with `--gw-table-count-scale`. Style the rest through the `toolbar`, `header`, `sort`, `sort-icon`, `row`, `cell`, `group`, `group-toggle`, `group-chevron`, `group-label`, `none`, `skeleton-row` and `skeleton` parts, with `--gw-table-header-height` (`2.5rem`) and `--gw-table-sort-icon-size` (`0.875rem`) for the header row. A `contained` table draws its own scrollbar thumb over the rows, the `scrollbar-thumb` part, so the header and group headings run its full width; its track starts under them, and it can be dragged. It takes the same `--gw-table-scrollbar-*` and `--gw-scrollbar-inner-*` properties as every component's scrollbars ([Scrollbars](/components#scrollbars)). Browsers without WebKit scrollbar styling, such as Firefox, keep their own thin scrollbar.

```ts
table.columns = [
  { id: "name", header: "Job", wide: true, cell: (job) => link(job) },
  { id: "last", header: "Last run", value: (job) => job.lastRun?.at ?? 0 },
];
table.rows = jobs;
```

For rows a server pages through, set `more` while there are older pages, and append the next on `more`. It fires once per page, as the skeleton rows near view, and again only after `rows` changes; the table is `aria-busy` in between. A page too short to fill the view asks for the next at once.

```ts
table.more = true;
table.addEventListener("more", async () => {
  const page = await runsBefore(table.rows.at(-1));
  table.rows = [...table.rows, ...page.rows];
  table.more = page.more;
});
```

## List

A long list of anything the page draws itself, such as cards or expansion panels, where a table's columns don't fit. Only the items on screen exist, windowed by TanStack Virtual against the window's scroll, or its own frame with `contained`, and items can be any height.

Set `items` and `draw` as properties. `draw(item, target)` draws an item into a container in the light DOM, so the page's own styles and components work in it, when it first scrolls into view and again when the item or `draw` changes. `keyOf` names each item, so it keeps its place and what was drawn across updates; an item scrolled away comes back as it was left, with its panels still open.

`groupOf` gathers the items under a heading for each value, in the order they first appear, with a chip counting each group. Headings sit flat on the page's own surface, under the items raised on it, and fold their items away when pressed.

| Attribute | What it does |
| --- | --- |
| `groups-collapsed` | Starts every group folded away |
| `toggled-groups` | The groups, by value, pressed from how they start |
| `contained` | Scrolls inside its own frame, up to `--gw-list-max-height` (`70vh`) |
| `storage-key` | Keeps the groups someone folded or opened in `localStorage` under this key |
| `estimate` | How tall an item is likely to be before it's measured, in pixels (`56`) |
| `label`, `empty-label` | Its name, and what it says with no items |

```ts
list.items = entries;
list.keyOf = (entry) => entry.id;
list.groupOf = (entry) => dayOf(entry.at);
list.draw = (entry, target) => render(entryPanel(entry), target);
```

## Markdown

<Demo id="markdown" layout="stack">
  <gw-markdown content={"Healed **3 consumers** of `@timmo001/oxlint-rules` after the release.\n\n- Bumped the pin in each\n- Re-ran their checks\n\nSee [the run](https://github.com/timmo001/groundwork) for the details."}></gw-markdown>
</Demo>

Written text, such as a description, a reason or an agent's summary, rendered from markdown with GitHub's extensions: tables, task lists, strikethrough and bare links. It's parsed with [micromark](https://github.com/micromark/micromark), which shows HTML in the text as text and drops links with unsafe protocols, so text from anyone is safe to show. Links open in another tab.

Short text renders at once. Long text is parsed when the page is idle, behind skeleton lines, then added a few blocks a frame, so it never holds up a click or a scroll. Headings are sized for text inside a page, and code blocks scroll in their own frame. Short plain values, such as a name or a version, stay plain text.

Code or a diff in a read-only view, which scrolls up to `--gw-code-max-height` (`32rem`), so a long one never stretches the page. Its toolbar wraps long lines, finds in it, with match case, regex and whole word, and copies it. The view takes focus, so the keyboard can select text, and Ctrl+F finds in it while it's focused. It's built on [CodeMirror](https://codemirror.net/), themed from the tokens.

| Attribute | What it does |
| --- | --- |
| `diff` | Reads it as a unified diff: added and removed lines are tinted and hunk headers are quiet |
| `language` | Highlights it as this language, with folds. `json` for now; any other goes in `extensions` |
| `wrap` | Wraps long lines rather than scrolling sideways; how it starts when it has a `storage-key` |
| `line-numbers` | Numbers the lines |
| `storage-key` | Keeps whether someone turned wrapping on or off in `localStorage` under this key |
| `find-shortcut` | Ctrl+F anywhere on the page finds in it while it's shown, for a viewer that fills the page |
| `label` | The view's accessible name, such as the file's name |
| `size` | The toolbar buttons' size, `xs` to `xl` as a button's (`small`). `--gw-code-tools-scale` sets any size in between |
| `tools` | The built-in tools that show, from `wrap find copy` (all three). Empty shows none |
| `wrap-label`, `find-label`, `copy-label`, `copied-label`, `copy-failed-label`, `toolbar-label` | The toolbar's words, for an app in another language |
| `phrases` | The find panel's words, as JSON keyed by CodeMirror's phrase, such as `{"next": "Weiter"}` |

It fires `change` when someone turns wrapping on or off. To fill the page, set `--gw-code-height` and `--gw-code-max-height: none`. In a fold, draw it with the expansion panel's `draw`, so the view isn't built until someone opens it.

Buttons in its `actions` slot join the toolbar before the built-in ones, such as a Download. The `extensions` property takes CodeMirror extensions of the app's own, added after Groundwork's, such as another language, its highlighting or a gutter:

```ts
import { javascript } from "@codemirror/lang-javascript";

code.extensions = [javascript()];
```

The toolbar's buttons are `gw-button`s, the `wrap`, `find` and `copy` parts, and `--gw-code-selection` colors selected text. `--gw-code-find-height` sets the find panel's field and buttons (`1.875rem`). The view shows a focus ring inside its frame when it has focus.
