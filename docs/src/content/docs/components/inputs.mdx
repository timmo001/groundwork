title: Inputs
description: Inputs, selects, checkboxes, switches and setting rows, kept in light DOM so forms work as on any page.
---

These render in light DOM, so password managers, `<label for>` and forms work as they do on any page. Inputs, checkboxes and switches use the native control; the select draws its own list and carries its value in a hidden input.

## Input

<Demo id="input" layout="stack">
  <gw-input label="Host" name="host" placeholder="192.168.1.20" hint="The address System Bridge listens on" info="Use the address of the machine running System Bridge on your network, such as 192.168.1.20 or desktop.local. Find it in System Bridge's settings, under Connection."></gw-input>
  <gw-input label="Port" name="port" type="number" value="9170" error="Port 9170 is already in use"></gw-input>
  <gw-input label="Token" name="token" type="password" autocomplete="current-password"></gw-input>
</Demo>

| Attribute | Values |
| --- | --- |
| `label` | The visible label, linked to the input |
| `type`, `name`, `value`, `placeholder`, `autocomplete` | Passed to the `<input>` |
| `hint` | One line of help under it, linked with `aria-describedby` |
| `info` | Longer help, opened from an (i) button by the label in a popover anchored to it |
| `error` | An error under it; marks the input invalid |
| `required`, `disabled` | Passed to the `<input>` |
| `icon` | SVG path data for an icon inside the field, before the text |
| `hide-label` | Keeps the label as the accessible name without showing it |

### In a form

Put inputs in a `<form>` with a `gw-button type="submit"`. Enter in any input submits the form, as it would with a native submit button, unless that button is `disabled` or `loading`.

<Demo id="input-form" layout="stack">
  <form method="dialog" style="display: grid; gap: var(--gw-space-3)">
    <gw-input label="Host" name="host" placeholder="192.168.1.20"></gw-input>
    <gw-input label="Port" name="port" type="number" value="9170"></gw-input>
    <gw-button type="submit" style="justify-self: start">Connect</gw-button>
  </form>
</Demo>

The list opens under the select, growing from it, and is a bottom sheet below 600px wide. From seven options it has a search field, focused as the list opens, that matches labels, descriptions, groups and `keywords`. Move with the arrow keys, Home, End and Page Up or Down, and pick with Enter. Only the options in view are rendered, so a list of thousands, such as time zones, stays quick.

Write `<option>` children, inside `<optgroup>`s for groups, with `data-icon` (SVG path data), `data-swatch` (a color shown as a dot) and `data-description`. Or set `options` to `[{ "value", "label", "description", "icon", "swatch", "group", "keywords" }]`. A hidden input carries the value in a form, and it fires `change`.

| Attribute | What it does |
| --- | --- |
| `label`, `name`, `value`, `hint`, `info`, `disabled` | As on an input |
| `placeholder` | Shown before anything's picked |
| `search` | `auto` (from seven options), `always` or `never` |
| `options` | The options, instead of `<option>` children |
| `multiple` | Picks several, kept in `values` |
| `inline-label` | Shows the label inside the trigger, before the value |
| `label-hidden` | Hides the label but keeps it for assistive technology |

### Inline label

In a toolbar or a row of filters, a label above each select takes more room than the controls. `inline-label` puts the label inside the trigger, in a quieter color before the value, so it reads as "Theme Glazing". The label still names the select for assistive technology. Use it where a select sits beside other controls; in a form, keep the label above, so every field lines up.

<Demo id="select-inline">
  <gw-select label="Theme" inline-label value="glazing">
    <option value="base">Base</option>
    <option value="glazing">Glazing</option>
    <option value="survey">Survey</option>
  </gw-select>
  <gw-select label="Sort" inline-label value="updated">
    <option value="updated">Updated</option>
    <option value="created">Created</option>
    <option value="name">Name</option>
  </gw-select>
</Demo>

### Several choices

<Demo id="select-multiple">
  <gw-select label="Language" inline-label multiple search="always">
    <option value="typescript" data-swatch="#3178c6" selected>TypeScript</option>
    <option value="python" data-swatch="#3572a5" selected>Python</option>
    <option value="go" data-swatch="#00add8">Go</option>
    <option value="rust" data-swatch="#dea584">Rust</option>
  </gw-select>
</Demo>

`multiple` picks several, for filters. Each pick toggles an option in `values` and the list stays open, with every chosen option ticked. The trigger shows the first choice and how many more, such as "TypeScript +1", and a Clear button under the list empties it. Mark the starting choices with `selected` on their `<option>`s, or set `values` to a JSON array. A form gets one hidden input per value, and `change` fires on every pick.

A `swatch` on an option draws a dot of that color before its label, such as a tag's or a language's color.

## Checkbox and switch

<Demo id="checkbox">
  <gw-checkbox label="Include hidden files" name="hidden"></gw-checkbox>
  <gw-switch label="Wake on LAN" name="wol" checked></gw-switch>
  <gw-switch label="Unavailable" disabled></gw-switch>
</Demo>

`gw-switch` is the same native checkbox drawn as a switch, with `role="switch"` so it's announced as one. Both take `label`, `name`, `value`, `checked`, `disabled` and `hint`. `label-hidden` keeps the label for assistive technology but hides it, for a control whose name is already beside it, as in a setting row.

## Range

<Demo id="range" layout="stack">
  <gw-range label="Volume" value="40" unit="%"></gw-range>
  <gw-range label="Brightness" value="128" max="255" hint="Applies as you let go"></gw-range>
  <gw-range label="Unavailable" value="60" disabled></gw-range>
</Demo>

A labeled native slider. While it's held, a bubble above the thumb shows the value, so a slider with no readout beside it still says where it is. It takes `label`, `name`, `value`, `min`, `max`, `step`, `unit`, `hint` and `disabled`; `unit` follows the value in the bubble and for assistive technology. The native `input` event fires while dragging and `change` when it's let go. `label-hidden` keeps the label for assistive technology but hides it.
