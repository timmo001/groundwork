title: Inputs
description: Inputs, selects, checkboxes, switches and setting rows, kept in light DOM so forms work as on any page.
---

These render in light DOM, so password managers, `<label for>` and forms work as they do on any page. Inputs, checkboxes and switches use the native control; the select draws its own list and carries its value in a hidden input.

| Attribute | Values |
| --- | --- |
| `label` | The visible label, linked to the input |
| `type`, `name`, `value`, `placeholder`, `autocomplete`, `inputmode`, `min`, `max`, `step`, `maxlength` | Passed to the `<input>` |
| `hint` | One line of help under it, linked with `aria-describedby` |
| `info` | Longer help, opened from an (i) button by the label in a popover anchored to it |
| `error` | An error under it; marks the input invalid and is announced |
| `required`, `disabled` | Passed to the `<input>` |
| `optional` | Adds "(optional)" after the label, for the few optional fields in a form that mostly requires them |
| `multiline`, `rows` | A `<textarea>` instead, starting `rows` lines tall (3 by default) and growing by its corner |
| `monospace` | The monospace font, with spellcheck off, for paths, commands and tokens |
| `reveal` | On a password field, a button at the end that shows and hides what's typed |
| `icon` | SVG path data for an icon inside the field, before the text |
| `label-hidden` | Keeps the label as the accessible name without showing it |
| `info-label`, `optional-label`, `reveal-label` | The (i) button's name, what `optional` adds, and the reveal button's name, for an app in another language. Default to "About" and the label, "(optional)", and "Show" or "Hide" and the label |

The list opens under the select, growing from it, and is a bottom sheet below `sheet-below`, 600px wide by default. From seven options it has a search field, focused as the list opens, that matches labels, descriptions, groups and `keywords`. Move with the arrow keys, Home, End and Page Up or Down, and pick with Enter. Only the options in view are rendered, so a list of thousands, such as time zones, stays quick.

Write `<option>` children, inside `<optgroup>`s for groups, with `data-icon` (SVG path data), `data-swatch` (a color shown as a dot), `data-description` and `disabled`. Or set `options` to `[{ "value", "label", "description", "icon", "swatch", "group", "keywords", "disabled" }]`. A disabled option still shows and can be reached with the keyboard, so give it a `description` saying why, but it can't be picked. A hidden input carries the value in a form, and it fires `change`.

| Attribute | What it does |
| --- | --- |
| `label`, `name`, `value`, `hint`, `info`, `info-label`, `disabled` | As on an input |
| `placeholder` | Shown before anything's picked |
| `search`, `search-from` | `auto` (the default), `always` or `never`, and how many options `auto` adds a search field from (`7`) |
| `options` | The options, instead of `<option>` children |
| `multiple` | Picks several, kept in `values` |
| `inline-label` | Shows the label inside the trigger, before the value |
| `label-hidden` | Hides the label but keeps it for assistive technology |
| `sheet-below` | The viewport width in pixels below which the list is a bottom sheet (`600`). `0` keeps it under the field |
| `clear-label`, `search-label`, `no-match-label` | The button that clears a multiple choice, the search placeholder, and what the list says when the search matches nothing, for an app in another language. Default to Clear, Search and No matches |

## Date picker

<Demo id="date-picker" layout="stack">
  <gw-date-picker label="Day" name="day" value="2026-11-11" max="2026-11-20" hint="Recordings end on the 20th"></gw-date-picker>
  <gw-date-picker label="Due" placeholder="No due date"></gw-date-picker>
</Demo>

A field that shows the chosen day and opens a calendar under it to pick another. The calendar takes focus as it opens; move with the arrow keys, Home and End to the week's ends and Page Up or Down by a month (with Shift by a year), and pick with Enter, Space or a click. Picking or Esc closes it and returns focus to the field, and Arrow Down on the field opens it. The value is a `YYYY-MM-DD` day, carried in a form by a hidden input, and it fires `change` when a day is picked.

| Attribute | What it does |
| --- | --- |
| `label`, `name`, `value`, `hint`, `info`, `info-label`, `disabled` | As on an input, with `value` as `YYYY-MM-DD` |
| `min`, `max` | The first and last days that can be picked, as `YYYY-MM-DD` |
| `marked`, `unmarked` | Days that stand out with a dot, as a JSON array, and how the rest show once any are: `normal` (the default), `dim`, or `disabled` to dim them and stop them being picked |
| `month` | The month the calendar shows, as `YYYY-MM`. It follows `value` |
| `placeholder` | Shown with no day chosen. Defaults to Choose a day |
| `format` | How the field writes the day, as JSON `Intl.DateTimeFormat` options. Defaults to the weekday, day, short month and year, "Wed, 11 Nov 2026" in British English |
| `locale`, `first-day` | The language for names, defaulting to the page's `lang`, and the week's first day, `0` for Sunday, defaulting to the locale's |
| `inline-label`, `label-hidden`, `icon-hidden` | Puts the label inside the field, hides it but keeps it for assistive technology, or hides the calendar icon |
| `size` | `xs` to `xl`, as on a select |
| `previous-label`, `next-label`, `marked-label` | The month buttons' names and what a marked day's name adds, for an app in another language. Default to Previous month, Next month and marked |
| `presets`, `preset-options`, `presets-label` | Shows shortcut buttons under the calendar, which ones as a JSON array, and the group's name. Defaults to Yesterday, Today and Tomorrow, and Shortcuts |

### Shortcuts

`presets` adds buttons under the calendar that pick a day in one click. Set `preset-options` to choose them: each has a `label` and moves from today by `days`, `weeks` or `months`, negative for the past, or picks a fixed `value`. A shortcut whose day is outside `min` and `max`, or on an unmarked day with `unmarked="disabled"`, is disabled.

  <gw-date-picker label="Due" presets preset-options='[{"label":"Today","days":0},{"label":"In 3 days","days":3},{"label":"Next week","weeks":1},{"label":"Next month","months":1}]'></gw-date-picker>
  <gw-date-picker label="From" presets preset-options='[{"label":"Today","days":0},{"label":"Last week","weeks":-1},{"label":"Last 30 days","days":-30},{"label":"Last year","months":-12}]'></gw-date-picker>
</Demo>

### Marked days

When only some days have something on them, such as recordings or bookings, set `marked` to them. Each month's days often come from a server, so listen for `month`, which fires with the new `YYYY-MM` in `detail` as the calendar moves, and set `marked` once they load. It fires when someone moves the month, not when the page sets `month` or `value`. With `unmarked="disabled"`, any day not marked is dimmed and can't be picked; keyboard focus still reaches it, so its date is read.

<Demo id="date-picker-marked">
  <gw-date-picker label="Day" inline-label value="2026-11-11" max="2026-11-12" unmarked="disabled" marked='["2026-11-02","2026-11-03","2026-11-05","2026-11-09","2026-11-10","2026-11-11","2026-11-12"]'></gw-date-picker>
  <gw-date-picker label="Day" inline-label value="2026-11-11" unmarked="dim" marked='["2026-11-02","2026-11-05","2026-11-11"]'></gw-date-picker>
</Demo>

```ts
import { on } from "@timmo001/groundwork-ui";

const picker = document.querySelector("gw-date-picker")!;

const loadDays = async (month: string) => {
  const response = await fetch(`/api/days?month=${month}`);
  const days: { date: string }[] = await response.json();

  picker.marked = days.map((day) => day.date);
};

on(picker, "month", (event) => loadDays(event.detail.month));
on(picker, "change", () => {
  location.hash = picker.value;
});
void loadDays(picker.month);
```

## Option list

<Demo id="option-list" layout="stack">
  <gw-option-list label="Time zone" search style="--gw-option-list-height: 14rem; max-width: 24rem" value="europe-london" options='[{"value":"europe-london","label":"London","description":"UTC+0","group":"Europe"},{"value":"europe-paris","label":"Paris","description":"UTC+1","group":"Europe"},{"value":"europe-helsinki","label":"Helsinki","description":"UTC+2","group":"Europe"},{"value":"america-new-york","label":"New York","description":"UTC−5","group":"Americas"},{"value":"america-chicago","label":"Chicago","description":"UTC−6","group":"Americas"},{"value":"america-los-angeles","label":"Los Angeles","description":"UTC−8","group":"Americas"},{"value":"asia-tokyo","label":"Tokyo","description":"UTC+9","group":"Asia"}]'></gw-option-list>

The searchable, windowed list inside the select and the [command menu](/components/overlays#command-menu), on its own for a list that picks in place, such as a side panel of time zones, or inside a popover or panel of an app's own. Type in its search field to filter by label, description, group or `keywords`; move with the arrow keys, Home, End and Page Up or Down; and pick with Enter or a click. It fires `pick` with the option's value and leaves what happens next to the page, so set `value` (or `values` with `multiple`) back once the pick takes. Call `reset()` each time it's shown, to clear the search and select the current option. Only the rows in view are rendered.

| Attribute | What it does |
| --- | --- |
| `options` | The options, as for the select |
| `value` | The selected option, ticked and selected first |
| `multiple`, `values` | Ticks every value in `values`, as JSON, and announces the list as multi-select |
| `label` | The list's accessible name |
| `search` | Shows a search field above the list |
| `placeholder`, `no-match-label` | The search placeholder and what it says when the search matches nothing, for an app in another language. Default to Search and No matches |

Rows have fixed heights, so the list knows where each sits without measuring. `--gw-option-list-option-height`, `--gw-option-list-described-height` and `--gw-option-list-group-height` set them in pixels, as plain numbers (`40`, `52` and `32`). `--gw-option-list-height` caps the list (`20rem`) and `--gw-option-list-search-height` sets the search row (`2.5rem`). Each option is the `option` part, with `option-icon`, `swatch`, `label`, `description`, `swatches` and `check` inside it. In forced colors the active row takes an outline in the system's highlight color.

```ts
import "@timmo001/groundwork-ui/define/gw-option-list.ts";

const list = document.querySelector("gw-option-list")!;

list.addEventListener("pick", (event) => {
  list.value = event.detail.value;
});
```

## Restyling the fields

The fields render in light DOM, so they have classes rather than parts, and their rules are in the `groundwork.components` layer with zero specificity. A page's own rule on any of these wins, with no `!important`:

| Class | What it is |
| --- | --- |
| `.gw-field-heading` | The row with the label, `optional` and the (i) button |
| `.gw-optional` | What `optional` adds after the label |
| `.gw-info` | The (i) button that opens `info` |
| `input`, `textarea` | The native control, which draws the field's box |
| `.gw-input-control` | Around an input, its icon and the reveal button |
| `.gw-reveal` | The button that shows and hides a password |
| `.gw-hint`, `.gw-error` | The line of help and the error under a field |
| `.gw-select-trigger`, `.gw-select-value`, `.gw-select-inline-label` | The select's button, its value and an `inline-label` |
| `.gw-select-popup`, `.gw-select-clear` | The select's list popover and its Clear button |
