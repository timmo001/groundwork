## App bar

    <gw-button variant="neutral" appearance="plain" href="#app-bar">Components</gw-button>

  </gw-app-bar>
</Demo>

A site or app header pinned to the top of the page: a brand in the `brand` slot, nav links in the default slot and icon buttons in `actions`. It runs the full width of the page with its content kept to `--gw-content-width`, or the [standard width](#lining-up-with-the-page) its `size` picks, and stays transparent until the page scrolls; then it gets a blurred surface and a bottom border, and sets `floating`.

For a page that opens with a hero, set `reveal-after` to a selector for it, such as `[data-hero]`. The bar then stays transparent and hides its brand until the hero scrolls out from under it, so the hero's large logo hands over to the bar's small one. A hidden brand takes no room: the nav starts at the edge, then slides over as the brand opens. `overlay` lays the bar over the top of the page instead of taking room, so the hero starts at the very top.

Below `menu-below`, 600px wide by default, the nav moves into a menu opened from a button, which closes on Esc, a click outside or picking a link. The bar sets `collapsed` while it does. The button leads, with the brand beside it. `menu-label` names that button. Raise `menu-below` when the nav and the actions need more room than a row has, so the actions stay in the bar while the nav folds away. A bar with no nav links, only a brand and actions, has no menu button at any width. `--gw-app-bar-menu-size` sizes the menu button (`2.5rem`).

### Nav and icon links

Nav links and icon links in `actions` are `gw-button`s with a plain `<a>` inside, so the links are in the page's HTML, for crawlers and `rel="me"`. `aria-current="page"` marks the page you're on. ### Lining up with the page

The bar keeps its content to `--gw-content-width`, with at least `--gw-space-3` either side. `gw-page` uses the same box, so a page inside it lines up with the bar at every width.

Both take a `size` for one of the standard widths. Give the bar and the page the same one so they line up:

| `size` | Width | For |
| --- | --- | --- |
| `narrow` | `--gw-content-width-narrow`, 44rem | Forms and settings |
| `default` | `--gw-content-width`, 90rem | Most pages |
| `wide` | `--gw-content-width-wide`, 120rem | Tables and dashboards |
| `full` | The whole window, less `--gw-space-3` either side | Boards and canvases |

```html
<gw-app-bar size="wide">…</gw-app-bar>
<gw-page size="wide">…</gw-page>
```

A `size` sets `--gw-content-width` for its element. To pick any other width, set `--gw-content-width` yourself: on `:root` for the whole app, or on one bar or page. Set the `--gw-content-width-narrow` or `--gw-content-width-wide` tokens to change what those sizes mean:

```html
<style>
  :root {
    --gw-content-width: min(100rem, 100vw - 6rem);
  }
</style>
<gw-app-bar>…</gw-app-bar>
<gw-page>…</gw-page>
```

`gw-page` must span the page, as the bar does. For content outside it, give the element the same box: `width: min(100% - 2 * var(--gw-space-3), var(--gw-content-width))` with `margin-inline: auto`.

The page header holds the page's `<h1>`, with an optional `icon` tile and `description`, its controls at the top right in the `actions` slot, and a back button or similar before the tile in the `start` slot. Set `level` for a part of a page that reads like a page of its own, such as a section shown only on some systems: from 2 the heading is that level and the header is smaller. A section title is an `<h2>` by default; set `level` for another. `--gw-page-header-start-height` is the `start` slot's least height (`3rem`), so a back button centers on the heading's first line.

  <gw-section heading="Older sensors" count="12" collapsed>
    <p>Folded away to start with.</p>
  </gw-section>
</Demo>

A section of a page under a heading that folds it away. It sits flat on the page's own surface, the same as the groups in a [list](/components/display/#list) or [table](/components/display/#table): a chevron, the `heading`, and a chip saying what `count` gives, such as how many items it holds. Pressing the heading folds the content away and pressing it again opens it. A section starts open, and `collapsed` starts it folded. It fires `toggle` when it changes.

`storage-key` keeps whether a section is open in this browser through the shared store, once someone folds or opens it, so it comes back as they left it. Content that's folded away stays in the page, hidden until found, so find-in-page still reaches it and opens the section.

Controls in the `actions` slot sit at the end of the heading's row and don't fold it. The heading is an `<h2>`, and `level` sets another. `--gw-section-gap` is the space between the heading and the content (`--gw-space-2`), and `--gw-section-count-scale` scales the chip (`0.8`).

Use a [section title](#page-header-and-section-title) for a heading that doesn't fold, and an [expansion panel](/components/display/#expansion-panel) for a raised panel of its own.

| Element | What it does |
| --- | --- |
| `gw-page` | Centers a page's content at `--gw-content-width`, or the standard width `size` picks |
| `gw-stack` | Stacks its children with the theme's gap |
| `gw-row` | Lines its children up and wraps them; `nowrap` stops that, and `scroll` scrolls them sideways instead |
| `gw-grid` | Fills columns at least `--gw-grid-min` (18rem) wide, and at most `max` of them |

`gap="s"` or `gap="l"` changes the gap of a stack, row or grid.

### Aligning the children

`justify` sets where a stack's or row's children sit along it: `start`, `center`, `end` or `between`. `align` sets where they sit across it: `start`, `center`, `end` or `stretch`. A row's children are centered across it and a stack's stretch across it by default. `center` and `end` keep children from being cut off at the start when they overflow, so a stack with a fixed height and `justify="center"` puts short content in the middle and still shows the top of tall content.

### Scrolling rows

A row of choices that would wrap onto a second line on a phone, such as a camera's presets or a set of filter chips, scrolls sideways instead with `scroll`. Its children stay on one line at their own size. Touch scrolls it as usual, and a mouse drags it: once the pointer has moved a few pixels it's a drag, and letting go never clicks the child under it. The ends fade while there's more to scroll that way, `--gw-row-fade` (`1.5rem`) deep, and a child focused with Tab scrolls clear of the fade. Its focus ring has room around it, so the row's edge doesn't clip it.

So nobody has to drag or swipe, a filled ‹ or › button fades in over each end while there's more to scroll that way, with the children fading out beside it, and fades out again at the end. Each press scrolls about one view, smoothly, or at once under reduced motion. They're 44px `gw-button`s named "Scroll left" and "Scroll right", which `scroll-left-label` and `scroll-right-label` translate; `--gw-row-scroll-button-scale` sizes them, the `scroll-button` part styles them, and `no-scroll-buttons` leaves them out.

`scroll="narrow"` wraps on a larger screen and scrolls only under 600px wide or 500px tall, the same rule that turns [popups into bottom sheets](/components/overlays#bottom-sheets-on-phones).

### Scroll buttons

The row's buttons work on any other horizontal scroller, such as a timeline's track. `scrollButtons(scroller, { start, end })` makes `start` scroll toward the inline start and `end` toward the inline end by about a view per press, and sets `hidden` on each while there's nothing more its way. It measures as the scroller scrolls, resizes or gains children, and as its items resize; a button that hides while focused hands focus to the other. Where the buttons sit, over the ends or beside the scroller, is up to the app.

```ts
import { scrollButtons } from "@timmo001/groundwork-ui";

const buttons = scrollButtons(track, {
  start: earlierButton,
  end: laterButton,
  // How far a press scrolls, 85% of the view by default
  step: (track) => track.clientWidth / 2,
  // To fade the ends or style the track as gw-row does
  onChange: ({ moreStart, moreEnd }) => {
    track.classList.toggle("more-earlier", moreStart);
    track.classList.toggle("more-later", moreEnd);
  },
});

// Measure again after a change it can't see, and stop when done
buttons.update();
buttons.stop();
```

`items` gives the elements whose size changes what overflows, when they aren't the scroller's own children, such as slotted ones. `scrollByView(scroller, "start" | "end")` scrolls one view on its own, such as from a key, and `scrollEdges(scroller)` reads what's out of view at each end.

### Capping the columns

On a wide screen a grid keeps adding columns. `max` (2 to 6) caps how many it shows, so the cards grow wider instead. Set `--gw-grid-max` for any other count. Narrow screens still drop to fewer columns at `--gw-grid-min`.
