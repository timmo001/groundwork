## Radius

A fixed scale, `--gw-radius-xs` (2px) to `--gw-radius-xl` (16px) and `--gw-radius-pill`, plus three the theme sets: `--gw-radius-control`, `--gw-radius-chip` and `--gw-radius-panel`.

## Elevation

`--gw-shadow-s`, `-m` and `-l`, from black at low opacity. Dark modes use stronger shadows, since a shadow reads less on a dark surface.

## Motion

Four durations: `--gw-motion-instant` (75ms), `--gw-motion-fast` (150ms), `--gw-motion-normal` (250ms) and `--gw-motion-slow` (350ms), with `--gw-motion-easing`, `cubic-bezier(0.2, 0, 0, 1)`. All drop to 1ms under `prefers-reduced-motion`.

Things that move, move fluidly. Inside a component that's a CSS transition: a toggle's picked pill slides to the new option, a switch's knob glides, menus, popovers and dialogs ease in from `@starting-style`, and notices fade in their corner. Color changes use the fast duration, and anything that travels uses the normal one.

Changes to the whole view use the View Transitions API through `withViewTransition()`, which falls back to changing straight away where it isn't supported. Switching theme or mode crossfades the page. Keep them simple, give each `view-transition-name` once, and remember only one runs at a time and that they work at document level, not inside a shadow root.

Content that arrives fades in rather than popping: a page once it has loaded, a panel's body, a list's results. Wrap it in [`gw-fade-in`](/components/feedback#fading-in). A loading placeholder fades in too, after a short wait, so a quick load never flashes one.
